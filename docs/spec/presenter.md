# Presenter Spec v0.1

HTMLslide Presenter is the runtime layer for opening compiler-generated `.deckpkg` files and driving a presentation session. Phase 6 starts with a package reader and single-screen rehearsal data model; desktop window placement and dual-screen UI are integration work on top of this API.

## Deck Package Input

Presenter opens `.deckpkg` ZIP archives generated by the compiler. Required package files:

```text
manifest.json
deck.html
deck.pdf
notes.json
presenter-settings.json
thumbnails/<slide-id>.png
```

`manifest.json` is authoritative for slide order, PDF page mapping, thumbnail paths, speaker-note sidecar path, and duration estimates. Presenter validation rejects unsafe package paths, missing package files, duplicate slide ids, duplicate PDF pages, slide-index mismatches, and notes sidecars that do not align with manifest slide order.

## Runtime Package API

`@htmlslide/presenter` exposes:

- `readDeckPackage(path)` to load and validate a `.deckpkg` file.
- `readDeckPackageBytes(bytes, options)` for tests and callers that already have archive bytes.
- `validateDeckPackage(path)` and `validateDeckPackageBytes(bytes, options)` to return CLI-compatible issue summaries without throwing.

The loaded `PresenterDeckPackage` includes:

- `manifest`: parsed package manifest.
- `notes`: parsed `notes.json`.
- `settings`: parsed presenter settings with default notes font size.
- `slides`: slide-order data with notes Markdown and thumbnail bytes.
- `artifacts.html`, `artifacts.pdf`, and `artifacts.thumbnails` for UI layers to render previews.

## Session State

Presenter session helpers are pure TypeScript state transitions. They do not require Electron, browser windows, or monitor APIs.

Session state stores:

- `mode`: currently `"rehearsal"`.
- `slideIndex` and `slideCount`.
- total planned duration in milliseconds from slide `durationSec`.
- timer start time, accumulated paused time, and current pause point.
- notes font size in pixels.
- screen overlay state: `"normal"`, `"black"`, or `"white"`.

Helpers include:

- `createPresenterSession(deckPackage, options)`
- `getCurrentSlide(deckPackage, state)`
- `getNextSlide(deckPackage, state)`
- `nextSlide(state)`
- `previousSlide(state)`
- `jumpToSlideIndex(state, index)`
- `jumpToSlideNumber(state, slideNumber)`
- `jumpToSlideId(deckPackage, state, slideId)`
- `pauseTimer(state, nowMs)`
- `resumeTimer(state, nowMs)`
- `getElapsedMs(state, nowMs)`
- `getRemainingMs(state, nowMs)`
- `increaseNotesFontSize(state)`
- `decreaseNotesFontSize(state)`
- `toggleBlackScreen(state)`
- `toggleWhiteScreen(state)`
- `getPresenterSessionView(deckPackage, state, nowMs)`

Invalid jump targets are no-ops. Navigation clamps at the first and last slides.

## Rehearsal Mode

Single-screen rehearsal mode uses one window or surface with:

- current slide preview
- next slide preview
- speaker notes
- elapsed and remaining time
- slide number and progress
- jump target controls
- black and white screen overlays
- notes font size controls

The runtime package only supplies data and state transitions. Rendering, focus handling, and persistence belong to the desktop/UI layer.

The desktop app now prepares compiler-generated `.deckpkg` input when Present is opened. It runs the shared export path
from the Electron main process, validates the returned package through `@htmlslide/presenter`, then passes package slide
order, timing, and notes into the renderer session. If package preparation fails, the app keeps the source-preview
rehearsal fallback so authors can still rehearse while fixing export issues.

The desktop shell also has a read-only direct package path for startup-opened `.deckpkg` files. In that flow the main
process validates the file without running project export or reading `deck.json`, the renderer builds a package-backed
workspace summary, and Presenter opens immediately from the package contents. Full OS document association remains
separate packaging work.

The desktop Presenter console also reads Electron display metadata and exposes a target-display selector with primary,
internal/external, scale, and resolution details. This is display discovery for the presenter workflow; separate audience
window placement and dual-screen synchronization remain future integration work.

## Keyboard Controls

Presenter keyboard actions are exposed through `PRESENTER_KEYBOARD_CONTROLS`, `getPresenterKeyboardAction(input)`, and `applyPresenterKeyboardAction(deckPackage, state, action, options)`.

| Key | Action |
| --- | --- |
| `ArrowRight` or `Space` | Next slide |
| `ArrowLeft` | Previous slide |
| `B` | Toggle black screen |
| `W` | Toggle white screen |
| `F` | Toggle fullscreen in the UI layer |
| `G` | Jump to slide in the UI layer |
| `T` | Pause or resume timer |
| `+` | Increase notes font size |
| `-` | Decrease notes font size |
| `Escape` | Exit presenter mode in the UI layer |

`fullscreen`, `jump`, and `exit` may require UI prompts or window APIs. The runtime maps those keys and leaves UI-only effects to the caller. `jump` can be applied by passing `jumpSlideIndex`, `jumpSlideNumber`, or `jumpSlideId`.

## Dual-Screen Future Work

Dual-screen presenter mode is a desktop integration layer over the same package/session state:

- audience view renders `deck.pdf` pages or `deck.html` slides full screen with no chrome.
- presenter console renders current/next previews, notes, timer, progress, and controls.
- window placement, fullscreen transitions, screen swap, and reconnect behavior remain outside `@htmlslide/presenter`.
